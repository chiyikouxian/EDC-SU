# Change: Add Main Control State Machine

## Why

硬件 B 当前需要先把 MSPM0 主控流程搭起来，作为后续视觉、底盘循迹、云台和蜂鸣器联调的统一入口。没有主控状态机时，各模块容易各自调通但无法形成比赛要求的完整时序。

## What Changes

- 基于 `empty/` 下的 LP_MSPM0G3507 NoRTOS 空白工程建立主控流程骨架。
- 增加三种运行模式的状态机框架：基础行进、基础导航、发挥导航。
- 定义蜂鸣启动/结束时序，保证最后一声启动蜂鸣与出发计时语义绑定。
- 定义视觉 UART 接收接口，接收树莓派输出的图形与目标点结果。
- 定义云台控制接口，支持回中、步进扫描、停止扫描。
- 定义底盘接口占位，包括电机锁定、解锁、找线、按目标点循迹、停车。
- 增加按键或拨码模式选择的抽象接口，便于后续接入实际硬件。

## Impact

- Affected specs: `main-control`
- Affected code: `empty/` MSPM0 空白工程，后续可能新增 `app/` 或 `modules/` 目录
- Affected collaborators:
  - 硬件 B：主控流程、云台、电源、蜂鸣器、接口集成
  - 视觉：需要按约定 UART 协议输出识别结果
  - 硬件 A：需要按主控接口暴露底盘状态和动作函数

## Out of Scope

- 不实现完整视觉识别算法。
- 不实现底盘循迹 PID 和路口路径表细节。
- 不进行最终硬件引脚分配锁定，除非用户单独确认引脚表。
- 不直接修改采购清单。
