# 电赛 C 题自动识别导航系统功能清单与三人分工

## 一、题目关键信息

### 1. 场地和硬件限制

- 场地为 200cm×200cm 白色喷绘布，黑色实线为唯一有效行驶路线，线宽约 1.8cm。
- 小车外边缘长宽建议不超过 15cm × 15cm。
- 小车只能搭载 1 个云台和 1 个摄像头，且云台、摄像头必须和车体一体。
- 行驶过程中不允许人工触碰小车，明显偏离黑线视为脱线。
- 指示纸为 A4 大小，垂直地面放置，纸中心距离地面 15cm。
- 附件图形包含 4 类：圆形、等边三角形、长方形、等边五边形。

### 2. 图形和目标点映射

| 图形 | 目标点 |
|---|---|
| 圆形 | A |
| 等边三角形 | B |
| 长方形 | C |
| 等边五边形 | D |

### 3. 计时和蜂鸣要求

- 启动前蜂鸣 3 声。
- 最后 1 声蜂鸣开始时同步开始计时。
- 到达目标点后蜂鸣 1 声，同时结束计时。
- 基础导航和发挥模式中，小车出发瞬间指示纸会被抽走，所以出发后不能再依赖指示纸定位，只能依靠黑线循迹和预设路径逻辑。

## 二、需要实现的功能

### 1. 基础行进模式

该模式 20 分，是最先应该打通的功能。

需要实现：

- 小车放在 A 点，初始方向任意。
- 启动后蜂鸣 3 声，最后 1 声开始计时并启动电机。
- 小车自动寻找黑线并进入循迹状态。
- 沿黑色实线经过中间小正方形，到达 C 点。
- 到达 C 点后车身覆盖 C 点，蜂鸣 1 声并停车。

核心难点：

- 初始方向任意，需要具备原地找线能力。
- 中间小正方形处容易误判，需要能识别交叉、拐点或节点。
- 速度越快越好，但不能脱线，因此需要速度闭环和循迹 PID。

### 2. 基础导航模式

该模式 30 分，是视觉和运动控制的第一次联调。

需要实现：

- 小车放在场地圆心，摄像头正对 CD 段支架位置。
- 摄像头识别 A4 纸上的图形。
- 根据图形映射出目标点 A/B/C/D。
- 识别完成后蜂鸣 3 声，最后 1 声开始计时并出发。
- 指示纸被抽走后，小车沿黑线行驶到正确目标点。
- 到达目标点后蜂鸣 1 声并停车。

核心难点：

- 图形识别必须稳定，至少要能在现场光照下区分圆、三角形、长方形、五边形。
- 识别和启动要有状态锁：识别未完成前电机不能动。
- 不同目标点对应不同路径，需要把“目标点”转换成循迹过程中的路口选择策略。

### 3. 发挥自动导航模式

该模式 50 分，是拉分项。

需要实现：

- 小车仍然放在圆心，摄像头初始正对 CD 段。
- 测评人员把支架随机放在下半圆环，也就是 AB 段一侧，此时目标处于摄像头初始视野盲区。
- 启动后车体不能移动、不能旋转。
- 只能控制云台带动摄像头扫描，找到 A4 指示纸。
- 锁定指示纸后识别内部图形。
- 根据图形确定目标点。
- 蜂鸣 3 声后出发，沿黑线行驶到对应目标点。

核心难点：

- 发挥部分识别阶段车体必须完全锁死，不能靠转车身找目标。
- 云台要覆盖下半圆环范围，扫描速度不能太快，否则画面模糊、识别失败。
- 指示纸可能有透视畸变，不能只按理想正视图判断。
- 云台扫描、图形识别、目标点映射、循迹出发需要形成完整状态机。

### 4. 系统级功能

最终作品应拆成以下模块：

| 模块 | 需要实现的功能 |
|---|---|
| 主控状态机 | 待机、自检、识别、云台扫描、蜂鸣、循迹、路口选择、停车 |
| 蜂鸣器 | 启动 3 声、到达 1 声，且和计时逻辑同步 |
| 摄像头识别 | A4 纸检测、图形分割、圆/三角形/长方形/五边形分类 |
| 云台控制 | 回中、角度扫描、目标锁定、扫描超时处理 |
| 循迹传感 | 黑线检测、偏差计算、丢线恢复、路口/节点识别 |
| 电机控制 | 左右轮 PWM、编码器测速、速度 PID、差速转向 |
| 路径决策 | 由目标点 A/B/C/D 决定路口转向和停车位置 |
| 电源与结构 | 电机、舵机、主控、摄像头稳定供电，车体尺寸合规 |
| 测试与报告 | 记录识别准确率、循迹成功率、平均用时、失败原因 |

## 三、推荐三人分工

建议分为 1 人视觉、2 人硬件。这里的“硬件”不只是焊线和装车，其中一人主攻底盘运动控制，另一人主攻系统集成、云台、电源和总流程。

### 1. 视觉负责人

主要目标：保证“看得见、认得准、给得出目标点”。

需要实现：

- 摄像头采集程序，完成曝光、白平衡、分辨率、帧率调试。
- A4 指示纸或图形区域检测。
- 四类图形识别：圆形、等边三角形、长方形、等边五边形。
- 输出统一识别结果，例如 `CIRCLE -> A`、`TRIANGLE -> B`、`RECTANGLE -> C`、`PENTAGON -> D`。
- 基础导航模式下的固定视角识别。
- 发挥模式下的云台扫描画面识别，能适应角度偏差和轻微透视畸变。
- 和主控约定通信协议：识别成功、识别失败、目标点编号、置信度或连续识别次数。

建议实现路线：

- 使用树莓派 4B + USB 摄像头，开发语言 Python，核心依赖 OpenCV。
- 优先传统视觉流程：灰度化→二值化→形态学→轮廓检测→`cv2.approxPolyDP` 多边形近似→边数/圆形度/长宽比区分 4 种图形。
- 树莓派算力充裕，可在本地实时预览调试，比嵌入式视觉模块开发效率高。
- 识别不必追求复杂 AI，现场图形固定，传统视觉更稳定、可调试。

需要学习：

- 摄像头基本参数：曝光、增益、白平衡、焦距、视场角。
- 图像预处理：灰度化、二值化、形态学开闭运算、滤波。
- 轮廓检测：面积、周长、边界框、最小外接矩形。
- 图形分类：边数、圆形度、长宽比、角点数。
- 透视畸变下的识别容错。
- 树莓派串口通信：通过 GPIO 的 UART（TX/RX）与 MSPM0 主控通信，需注意树莓派 3.3V 电平与 MSPM0 电平匹配。
- 现场调试方法：采集样张、记录误识别样例、建立阈值表。

交付物：

- `detect_shape()` 或等价识别函数。
- 图形到目标点的映射表。
- 识别稳定性测试记录，至少每种图形多角度、多光照测试。
- 和主控联调成功的识别数据输出。

### 2. 硬件负责人 A：底盘运动与循迹控制

主要目标：保证“小车跑得稳、跑得快、不脱线、能到点停车”。

需要实现：

- 小车底盘选型和安装：双轮差速、万向轮/滑轮、重心控制。
- 电机驱动电路调试，例如 TB6612、DRV8833 或其他电机驱动。
- 编码器测速，完成左右轮速度闭环。
- 红外循迹阵列安装和标定，建议 6 路或 8 路红外。
- 黑线偏差计算，把传感器状态转换成位置误差。
- 循迹 PID：直线、弯道、小正方形、路口处都要稳定。
- 原地找线逻辑：基础行进模式中初始方向任意，需要先旋转搜索黑线。
- 丢线保护：短暂丢线后按历史方向找回，长时间丢线停车。
- 路口/节点识别：为 A/B/C/D 目标点路径选择提供可靠触发点。
- 终点停车逻辑：车身覆盖目标点后停车，不能过冲太多。

建议实现路线：

- 先低速完成闭环循迹，再逐步提高速度。
- 先跑单一路径 A 到 C，再加入圆心到 A/B/C/D 的多目标路径。
- 路口选择不要一开始做得太复杂，可以用“节点计数 + 目标点转向表”实现。
- 对每段路径建立调试记录：传感器状态、转向动作、是否丢线、到点误差。

需要学习：

- PWM 电机控制和 H 桥驱动。
- 编码器测速和速度 PID。
- 差速小车运动学：左右轮速度差和转弯半径关系。
- 红外循迹传感器原理和阈值标定。
- 位置式 PID / 增量式 PID。
- 路口识别、状态机、节点计数。
- 机械结构对循迹的影响：传感器离地高度、传感器到轮轴距离、轮胎打滑。

交付物：

- 可稳定循迹的底盘。
- 基础行进模式 A 到 C 完整跑通。
- 路口识别函数和路径动作表。
- 目标点停车调试数据。

### 3. 硬件负责人 B：系统集成、云台、电源与主控流程

主要目标：把视觉、底盘、云台和蜂鸣时序整合成完整系统。

需要实现：

- 主控硬件连接：电机驱动、编码器、红外阵列、蜂鸣器、按键、树莓派串口、云台舵机。
- 电源系统：电机供电、舵机供电、MSPM0 供电、树莓派供电（5V/3A，需独立稳压或充电宝）分开规划，避免电机启动导致主控或树莓派掉电。
- 云台结构安装：保证摄像头中心高度、角度、线缆不拉扯。
- 云台控制程序：回中、角度限位、扫描步进、目标锁定。
- 发挥模式下的扫描策略：从初始 CD 方向转向 AB 侧下半圆环，分段扫描并等待视觉识别。
- 全局状态机：待机、自检、固定识别、云台扫描、识别完成、蜂鸣 3 声、启动循迹、到达停车、结束蜂鸣。
- 蜂鸣器时序：最后一声蜂鸣和电机启动、计时开始严格同步。
- 模式选择：基础行进、基础导航、发挥导航最好通过按键/拨码开关选择。
- 联调接口：接收视觉目标点，调用底盘路径，处理异常。

建议实现路线：

- 先把所有模块分别点亮：蜂鸣器、按键、舵机、电机、传感器、摄像头通信。
- 再做统一状态机，不要把所有逻辑都写在一个循环里。
- 发挥模式中，扫描阶段必须给电机驱动加软件锁和硬件使能锁，防止误动。
- 电源要优先可靠：舵机和电机电流波动很大，主控和摄像头需要稳压、滤波、共地。

需要学习：

- 单片机 GPIO、PWM、定时器、中断、串口通信。
- 舵机 PWM 控制和角度标定。
- 电源稳压、降压模块、共地、滤波电容、线径和电流余量。
- 嵌入式状态机设计。
- 模块通信协议设计：命令、状态、超时、重试。
- 整车布线和抗干扰：电机线、舵机线、摄像头线分开走线。
- 设计报告写作：系统方案、电路图、程序流程图、测试数据。

交付物：

- 完整接线图和电源分配图。
- 云台扫描和锁定控制程序。
- 主控状态机。
- 三种模式的启动、蜂鸣、停车流程。
- 联调测试表和设计报告素材。

## 四、三人之间的接口约定

为了避免后期联调混乱，建议尽早约定接口。

### 1. 视觉到主控

建议输出：

| 字段 | 含义 |
|---|---|
| `shape` | `circle` / `triangle` / `rect` / `pentagon` / `none` |
| `target` | `A` / `B` / `C` / `D` |
| `valid` | 是否连续多帧识别成功 |
| `confidence` | 可选，识别置信度或稳定帧数 |

主控只关心最终目标点，视觉内部如何识别不影响底盘。

### 2. 主控到视觉/云台

建议命令：

| 命令 | 含义 |
|---|---|
| `START_FIXED_DETECT` | 基础导航固定角度识别 |
| `START_SCAN_DETECT` | 发挥模式云台扫描识别 |
| `STOP_DETECT` | 识别结束 |
| `RESET_CAMERA` | 摄像头或视觉模块复位 |

### 3. 主控到底盘

建议接口：

| 命令 | 含义 |
|---|---|
| `FIND_LINE` | 原地找线 |
| `FOLLOW_LINE` | 正常循迹 |
| `GO_TARGET_A/B/C/D` | 按目标点执行路径 |
| `LOCK_MOTOR` | 锁电机，禁止运动 |
| `STOP_AT_TARGET` | 到点停车 |

### 4. 路径策略

建议由硬件负责人 A 和 B 一起现场测量路线后建立路径表，例如：

| 目标点 | 路口动作序列 |
|---|---|
| A | 待实测后填写 |
| B | 待实测后填写 |
| C | 待实测后填写 |
| D | 待实测后填写 |

不要只凭示意图写死路径，最终应以实际喷绘布、传感器触发结果和车辆转弯半径为准。

## 五、开发优先级

### 第一阶段：拿基础分

目标是基础行进模式稳定跑通。

- 硬件 A 完成底盘、电机、红外循迹。
- 硬件 B 完成主控、蜂鸣器、按键、电源。
- 视觉负责人先调通摄像头，不阻塞底盘。
- 输出结果：A 点到 C 点稳定完成，能蜂鸣启动和停车。

### 第二阶段：打通基础导航

目标是图形识别后跑到 A/B/C/D。

- 视觉负责人完成固定角度图形识别。
- 硬件 A 完成多目标路径和路口动作。
- 硬件 B 完成识别结果接收、目标点映射和状态机。
- 输出结果：4 种图形分别能触发 4 个目标点路径。

### 第三阶段：完成发挥项

目标是云台扫描盲区并识别。

- 硬件 B 完成云台扫描角度范围和速度调试。
- 视觉负责人完成非正视角识别容错。
- 硬件 A 保证识别完成后的路径仍然稳定。
- 输出结果：车体不动，云台找到指示纸，识别后自动出发。

### 第四阶段：提速和报告

目标是提高成功率、缩短时间、完善报告。

- 记录每种模式至少 10 次测试结果。
- 分别统计识别成功率、循迹成功率、平均用时、失败原因。
- 优化速度 PID、循迹 PID、云台扫描速度、识别阈值。
- 完成系统框图、电路图、程序流程图、测试数据表。

## 六、风险点和应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 光照变化导致图形识别错误 | 目标点跑错，直接丢分 | 固定摄像头参数，使用二值化阈值自适应或现场标定 |
| 红外循迹误判路口 | 路径错误或脱线 | 传感器阵列加宽，使用节点计数和动作延时滤波 |
| 速度过快导致转弯冲出黑线 | 基础模式失败 | 直线高速、弯道降速，按路口状态动态限速 |
| 舵机/电机拉低电源 | 主控复位、树莓派掉电 | 电机和舵机独立供电，MSPM0 和树莓派各自稳压，树莓派建议独立 5V/3A 供电 |
| 云台扫描太快 | 画面模糊、漏检 | 步进扫描，每个角度停留若干帧后再判断 |
| 发挥模式识别阶段车体误动 | 违规 | 扫描阶段锁死电机驱动，使能脚关闭，软件状态机禁止运动 |
| 路径表和实际场地不一致 | 到不了目标点 | 用实际场地逐段标定，不只依赖题图 |

## 七、最小可行方案建议

推荐采用“红外循迹 + 传统视觉识别 + 一维云台”的方案。

- 循迹：6 路或 8 路红外阵列负责黑线检测，比摄像头循迹更容易稳定。
- 运动：双轮差速编码器底盘，左右轮速度 PID。
- 视觉：树莓派 4B + USB 摄像头，Python + OpenCV 识别图形，优先传统轮廓算法。
- 云台：一维水平舵机云台即可覆盖发挥部分搜索范围。
- 主控：MSPM0 负责运动控制、状态机、蜂鸣器、云台舵机；树莓派与 MSPM0 之间通过串口通信。

这个方案的分工清晰：视觉负责人专注识别，硬件 A 专注跑线，硬件 B 专注整车集成和流程控制。比赛中最重要的是稳定拿分，先保证基础行进和基础导航，再投入时间优化发挥部分。
